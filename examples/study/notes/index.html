Windows vs GROUP BY · PARTITION BY / ORDER BY

Consolidated 2026-08-01 · quiz 6.5/8 (~81%) · status: ✅ consolidated, 2 ⚠️ points

"GROUP BY squashes the rows into one per group. A window function looks at the same group but leaves my rows alone — every order row stays, and the aggregate rides along as an extra column."

OVER (PARTITION BY customer_id) = "compute per customer, but don't collapse". ORDER BY inside OVER turns the window into a sequence; without it the window is just a bag.

Worked example

SELECT order_id, customer_id, amount,
       SUM(amount) OVER (PARTITION BY customer_id)  AS customer_total,
       ROW_NUMBER() OVER (PARTITION BY customer_id
                          ORDER BY amount DESC)     AS rn
FROM orders;

Customer 101's 50.00 tie: ROW_NUMBER → (1, 2) · RANK → (1, 1, 3) · DENSE_RANK → (1, 1, 2).

Insight

HAVING filters groups after collapsing; a window filters rows by a group-level fact while keeping the rows — the whole reason top-N-per-group needs windows.

⚠️ Review: RANK counts rows, DENSE_RANK counts distinct values — predicted RANK's post-tie value wrong twice (session + quiz). Drill before Stage 2.
⚠️ Review: default frame with ORDER BY is RANGE UNBOUNDED PRECEDING — can repeat the phrase, can't yet explain the consequence. Stage 2 covers it.
