# Skill: SLD Conventions

The contract every SLD skill operates under. Load this before planner, teacher, evaluator, reviewer, or quiz does anything.

## Core thesis

Learning follows the same discipline behavioral-SDD applies to code: a written, challenged plan before execution; versioned state; explicit gates. Here, "execution" is socratic discussion, "review" is a quiz, and "done" means *consolidated in the learner's own vocabulary* — not "I read the material."

## State files (all under `study/`)

- `study/PLAN.md` — the curriculum. Source of truth for topics, formulas, deliverables, and domain anchors. Written by the planner; teacher and evaluator never invent content beyond it.
- `study/progress.md` — the staged checklist. One section per stage; within each stage, a **Concepts** list and a **Practice** list; each stage ends with a ✅ stage criterion line. Plus a session-history table at the bottom. Legend: `[ ]` not started · `[~]` started/discussed · `[x]` consolidated.
- `study/notes/<topic-slug>.md` — per-topic consolidated notes, written by the teacher *after* discussion, reflecting the learner's actual understanding. Fragile points marked ⚠️.
- `study/notes/index.html` — self-contained HTML index of everything consolidated, organized by stage, highlighting ⚠️ points. Regenerated by the teacher.
- `study/quiz-history.md` — quiz results: date, topic, score, missed questions with the concept behind each miss. Written by the evaluator; the quiz skill appends compact "Quick quiz" blocks to it.
- `study/review-history.md` — retention state: a per-topic review schedule (last review, interval, next due) and a log of review sessions with the concepts missed. Written by the reviewer.
- `study/backlog.md` — deferred subjects (outside the plan's scope/timebox).

## Gates

- No studying without a plan: if `study/PLAN.md` does not exist, run the planner first.
- A topic moves `[ ]` → `[~]` when discussed with the teacher, and `[~]` → `[x]` only when consolidated: discussed with the teacher AND/OR ≥80% on an evaluator quiz covering it.
- Consolidated is not permanent: a `[x]` topic enters the review schedule, and goes back to `[~]` if it scores below 50% on a reviewer battery.
- A quick quiz (`quiz` skill) never moves a checkbox in either direction: multiple choice measures recognition, not recall. Its misses are only logged.
- A stage is done only when its ✅ criterion is met — the criterion must be demonstrable (e.g. "explain X without consulting the source"), never "finished reading".
- Consolidated notes record the understanding built in conversation, including the doubts — never a generic summary the AI would write alone.

## Hand-offs

planner defines → teacher discusses and consolidates → evaluator measures and promotes → reviewer brings consolidated topics back on a spaced schedule → misses feed back into the next teacher session. The quiz skill sits outside the loop: a quick check at any point, whose logged misses the reviewer and teacher pick up. Every session (teacher, evaluator, reviewer, or quiz) appends one row to the history table in `study/progress.md`.

## Language

Respond and write study documents in the language the user speaks. Keep domain jargon in its original language (as defined by the plan's domain anchors). Code and identifiers in English.
